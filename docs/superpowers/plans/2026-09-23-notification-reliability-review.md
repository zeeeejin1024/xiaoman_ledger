# 2026-09-23 通知可靠性优化与复盘

## 本轮范围与发布状态

用户要求「提出值得优化的点并完成」。本轮针对已定位的通知、记账保存与首页刷新缺陷修复，不重做 UI，不增加常驻后台，不改服务器配置。

仍处于开发验证阶段：版本保持 `7.0.10+37`，不构建、不替换 APK。等待用户确认没有新增需求或明确要求发布后，再统一升版、打包与实机安装。

## 已实现的优化

| 问题 | 原因 | 本轮修改 |
| --- | --- | --- |
| 当天已记账仍可能提醒 | 跳过今天仅在单次调度调用中存在；首页重新调度丢失该信息；重复时间组件不能表达明确的明天起点 | 成功保存今天账单后持久记录日期；首页同步账单时补齐标记；每日使用 30 天单次任务窗口，无每日重复组件 |
| 改提醒过程中丢失旧任务 | 先清空再安排，一旦平台出错原任务也消失 | 先替换固定 ID、核验队列，再清理旧任务；超限参数先校验再操作 |
| 生活费提醒失败后不重试 | 页内提示和系统通知共用去重记录；未获权限也被算成已发 | 两种记录分开；平台提交成功才记录；失败/未授权可在下次刷新重试；关闭提醒时不消费记录 |
| 高档阈值后又弹低档提示 | 仅对同一阈值去重 | 100% 覆盖低档，90% 覆盖 75%；同档串行处理防重复 |
| 钱包提示与钱包页面不一致 | 读取旧本地分类预算，没有使用服务端钱包分类绑定汇总 | 使用 `/wallets` 的钱包 ID、预算及实际支出；网络失败不回退过时数据，不消费去重记录 |
| 一类提醒失败导致其他提醒消失 | 每日失败后提前返回，周/月安排没有执行 | 各规则独立处理错误；整体仍报告未全部成功 |
| 通知设置转圈/按钮不能再操作 | 缺少失败态、finally、返回系统设置时的刷新 | 读取失败可重试；保存期间锁定；返回前台重新读取；保存后的状态读取不重复调度 |
| 状态误导 | 开关开启就显示报告已自动生成；定时测试暗示 15 秒必达 | 周/月检查对应队列 ID，明确打开后加载报告；测试区分队列登记与实际收到 |
| 记账已成功却停在弹窗 | 保存流程等待通知，通知异常向外冒泡；网络失败未恢复按钮 | 主保存与通知隔离；保存成功关闭弹窗，通知后台刷新；失败恢复按钮并保留幂等请求标识 |
| 语音返回首页数字未更新 | 路由返回没有刷新首页 | 返回语音页后重新加载；语音、截图和手动均经统一成功保存日期标记 |
| 启动停留等待通知 | 登录后的导航等待通知调度和网络规则拉取 | 通知准备独立执行并捕获异常，不阻塞首页导航 |
| 保存成功、首页刷新断网后当天仍提醒 | 通知更新依赖首页 GET 成功 | 所有记账方式的统一保存 API 独立触发通知恢复，不依赖首页；已删除手动页重复回调 |
| 旧规则清理失败挡住其他提醒 | 创建协调器等待迁移，清理异常中断创建 | 清理失败保留待重试标记，其他规则继续运行；下次恢复重试迁移 |

## 自动化验证范围

- 单元测试：日期持久化、独立提醒记录、去重档位、开关、权限拒绝及重试。
- 平台适配器测试：真正的 Dart 通知服务通过模拟 MethodChannel 登记、替换、取消及核验 ID；验证 30 天单次窗口和旧任务迁移失败。
- 协调器集成测试：每日失败不阻断周/月；使用服务端钱包汇总；服务器失败不触发旧分类预算；记账后再刷新仍从明天开始。
- Widget 测试：读取失败重试、系统设置返回、保存期间锁定、保存失败恢复、队列状态、诊断测试失败后重试、成功记账不受通知异常阻碍、慢通知初始化不挡首页。
- 小屏大字体布局检查纳入测试。

## 尚不能等同于已验证的内容

1. 2026-09-23 本轮 `adb devices -l` 返回空设备列表，未在手机安装、锁屏、省电、重启或测试真实通知送达。
2. 测试中的平台通道模拟证明调度参数和错误处理，不等同于 Android ROM 实际执行结果。
3. 每日提醒预排 30 天，打开首页/通知中心等恢复路径续排；超过窗口长期不打开应用将停止每日提醒。不是无限后台续排。
4. 使用 `inexactAllowWhileIdle`，不承诺分钟级或 15 秒精确到达。平台接受请求、队列有 ID、用户收到是不同状态；单通道关闭、系统限制仍需实机检查。
5. iOS 接口保留，本轮没有 iOS 构建或设备验证。
6. 周报/月报是本机「查看报告」提醒，报告打开后获取；本轮没有实现服务器推送/离线自动生成报告。
7. 预算、生活费基于应用读取到账单后检查，并非后台持续监听每一笔消费；无新账单数据时不能感知真实消费。
8. 本轮不改变已有 Release 签名配置；正式面向应用商店前需单独规划发布签名和渠道测试。
