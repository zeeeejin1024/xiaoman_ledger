# 小满记账智能化与交互升级路线图

## 1. 目标

本路线图覆盖以下产品目标：

1. 周报和月报从固定统计文案升级为可信、可执行的智能报告。
2. 截图记账支持识别和手动修改大类、子类，不再只围绕商家信息。
3. 语音记账接入真实录音，并在提高准确率的同时控制模型成本。
4. 钱包从“单个子分类预算”升级为“可绑定多个分类的预算容器”。
5. 所有记账入口保存成功后返回首页，避免重复记账。
6. 通知模块先完成独立设计和验证方案，未经确认不删除旧实现。
7. 底部导航支持点击、横滑、震动和克制的流星轨迹效果。
8. 首页标题固定为“小满记账”，副标题允许通过独立入口修改。
9. 底部导航删除钱包，只保留首页的钱包入口。
10. 统计图在极端差距下提高小数值的可见性，但保留真实金额。
11. 所有缓存页面与弹层同步响应主题切换。
12. “我的”页面扩大资料编辑入口的触摸范围，不放大图标。

## 2. 设计原则

- 金额计算、分组、比较和预算判断必须由确定性代码完成，模型不能编造数值。
- AI 只处理自然语言理解、截图语义补全和报告表达；低置信度结果必须让用户确认。
- 分类是每笔账单的必填信息，但允许只选择大类，避免强迫用户填写过细。
- 一次保存请求只能生成一组账单，所有保存按钮都要防重复点击。
- 页面缓存保留数据和滚动位置，主题变化只刷新视觉子树，不重新请求接口。
- 动效必须可中断、跟手，并在低性能设备或“减少动态效果”开启时降级。
- 每个可安装版本同时更新 `pubspec.yaml`、`AppConstants.appVersion` 和版本测试。
- Android 先交付并实机验证，接口和数据模型为 iOS 保留兼容空间。

## 3. 现状与主要问题

### 3.1 周报和月报

当前主页面调用 `/stats/weekly` 和 `/stats/monthly`。后端负责基础聚合，前端负责拼接摘要和建议。旧的 `/ai/report/weekly` 名称带有 AI，但内部仍是关键词模板，而且主周报页面没有使用该接口。

当前缺陷：

- `/stats/weekly` 没有返回页面期待的 `suggestions` 字段，建议区域经常只显示兜底文案。
- 周报只比较本周与上周总额，没有类别变化、异常交易、预算偏差和行为趋势。
- 月报仅根据结余正负及最大支出类别给出通用建议。
- 报告缺少数据充分度说明，少量账单也会产生看似确定的结论。

### 3.2 截图记账

当前截图发送给 `qwen-vl-plus`，提示模型从数据库子分类中选择类别。后端 `_resolve_category_id` 只查找 `parent_id` 非空的子分类，前端识别结果卡只编辑金额、商家、备注和日期，没有类别选择器。

当前缺陷：

- 用户不能在识别结果页纠正类别。
- 大类不能作为最终选择。
- 无法匹配时可能使用无语义的默认 ID。
- 商家被识别但没有形成可复用的“商家到分类”习惯。
- 批量保存逐笔吞掉异常，用户看不到哪一笔失败。

### 3.3 语音记账

当前“语音记账”前端只有文字输入，调用 `/ai/parse`。后端使用金额正则和关键词表完成解析。`/ai/voice` 与讯飞听写服务虽已存在，但前端未上传音频。

当前缺陷：

- 功能名称与实际能力不一致。
- 口语数字、否定、退款、多人付款和一句多笔等表达处理不足。
- 分类匹配失败后会回退到该类型第一个子分类，可能静默记错账。
- 置信度只按是否识别出金额和类别简单累加，不能反映真实歧义。

### 3.4 钱包

当前钱包预算保存在本地 `SharedPreferences`，键为子分类 ID；服务器另有一套基于 `wallet_type` 的旧钱包接口。钱包统计只累计账单的精确 `categoryId`。

当前缺陷：

- 账单必须选中同一个子分类，才能进入对应钱包。
- “餐饮”大类无法自动覆盖早餐、午餐、晚餐等子类。
- 本地和服务端存在两套含义不同的数据模型。
- 自定义钱包无法自然绑定多个分类。

## 4. 总体架构

### 4.1 分类选择统一

新增统一的分类选择组件和选择结果：

```text
CategorySelection
  categoryId       最终保存的分类 ID
  parentCategoryId 所属大类 ID；选择大类时与 categoryId 相同
  specificity      parent | leaf
  source           user | merchant_rule | parser | vision
  confidence       0.0 - 1.0
```

手动记账、截图确认和语音确认都使用同一个分类选择组件。选择大类时可以直接保存；点击独立展开按钮后再选择子类。金额有效但没有分类时，保存按钮不可用并显示“请选择分类”。

### 4.2 钱包规则

钱包不再等同于一个分类，而是一个预算规则容器：

```text
WalletBudget
  id
  name
  monthlyLimit
  color
  categoryBindings[]

WalletCategoryBinding
  walletId
  categoryId
  includeDescendants
```

绑定“餐饮”且 `includeDescendants=true` 时，早餐、午餐、晚餐、外卖等记录全部计入该钱包。绑定具体子类时只统计该子类。一个账单默认最多进入一个消费钱包；出现多条规则冲突时，优先使用更具体的子类规则，其次使用用户设定的排序。

现有本地预算迁移为“绑定单个子分类”的钱包规则，不丢失金额。服务器旧 `wallet_type` 数据只读取一次并转换，随后使用统一模型。

### 4.3 混合智能管线

```text
输入
  -> 确定性预处理
  -> 商家个人规则
  -> 本地/服务端规则解析
  -> 置信度判断
  -> 低置信度才调用模型
  -> 统一确认卡
  -> 用户修正
  -> 保存账单和学习规则
```

成本控制规则：

- 金额、日期和常见类别能被规则明确解析时不调用语言模型。
- 截图先裁剪、压缩并去除重复图片哈希；相同图片短期内复用结果。
- 商家历史已有稳定分类时，用视觉模型识别金额和商家后直接套用个人规则。
- 只有类别歧义、一句话多笔、退款语义冲突等情况调用小型语言模型。
- 用户确认后的“商家→类别”映射达到两次一致选择后自动生效；一次选择只作为候选。
- 报告只把聚合特征交给模型，不上传原始完整流水；按用户、周期和数据版本缓存。

### 4.4 智能报告

报告引擎分两层：

1. `ReportInsightEngine` 计算事实：总额、类别占比、近四周/近三月基线、异常交易、预算进度、重复支出、无消费日、收入周期和数据充分度。
2. `ReportNarrator` 将事实组织成自然语言；模型不可修改数值，每条建议必须引用事实 ID。

当周期内少于 5 笔有效账单时，只展示事实摘要和“数据较少”提示，不生成强结论。报告最多给 3 条建议，每条包含“发现、影响、下一步”，例如“本周外卖比近四周均值高 38%，下周减少 2 次预计可少支出约 ¥46”。预计金额由规则引擎计算。

### 4.5 导航与页面状态

底部导航固定为：首页、统计、存钱、流水、我的。钱包通过首页卡片进入。

点击导航时，选中底托在约 240ms 内移动到目标入口，同时出现短雾青尾迹和蔷薇莓落点；到达时触发一次轻震。横滑时，页面位置、底托和光点跟随手指，跨过入口中心时每个入口最多震动一次。动画只使用 `Transform`、`Opacity` 和独立 `RepaintBoundary`，不使用实时大面积模糊或持续粒子。

页面继续采用懒加载缓存，但所有页面的视觉根节点统一订阅 `AppColors.notifier`。主题变化不销毁页面状态、不重载接口。路由推入的报告页、钱包页、设置页和弹层同样使用统一主题边界。

### 4.6 首页与个人资料

- 首页主标题固定显示“小满记账”，移除标题点击编辑能力。
- 副标题默认“今天也留一点余地”，后方提供文字按钮“更改”。
- 副标题限制 16 个中文字符或等价字符长度；去除首尾空格，空内容恢复默认值。
- 点击副标题本身不触发编辑，只有“更改”按钮打开编辑弹层。
- 个人资料入口整行使用不透明命中区域；所有可点击图标的命中范围至少 48×48 逻辑像素，图标视觉尺寸保持现状。

### 4.7 统计图视觉缩放

真实金额保持不变，提示框和文本始终显示真实值。仅当同组非零最大值与最小值比例大于 8 时，柱高采用平方根缩放：

```text
visualHeight = sqrt(value / maxValue) * chartHeight
```

图表展示“已优化显示比例”提示，避免用户把视觉高度误认为线性金额比例。比例不超过 8 时继续使用线性刻度。

### 4.8 通知重构边界

通知重构在独立设计确认前不删除现有页面和调度代码。设计阶段必须先交付：

- 新设置页线框和字段定义。
- `NotificationRule -> SchedulePlan -> PlatformScheduler -> AuditState` 状态机。
- 权限缺失、精确闹钟不可用、Doze、重启、升级、时区变化的恢复策略。
- Android 16 实机验收矩阵及 iOS 接口契约。
- 旧偏好迁移、旧通知 ID 取消和回滚方案。

新页面面向普通用户只显示权限状态、提醒开关、时间和“下一次提醒”。即时/定时测试、队列数量和系统诊断移入开发诊断页。

## 5. 保存后的导航规则

- 首页底部弹层手动记账：保存成功后关闭弹层，仍显示首页并刷新数据。
- 从通知或其他页面进入记账：保存成功后清空中间路由并回到首页。
- 截图批量保存：全部成功后关闭结果页并回首页；部分失败时停留结果页，只保留失败项并显示原因。
- 语音记账：保存成功后回首页；用户返回但未保存时保留一次草稿。
- 保存按钮提交期间禁用，客户端生成一次性请求 ID；服务器重复收到同一 ID 时返回原结果，不新增记录。

| 阶段 | 版本 | 交付范围 |

| 分类与钱包 | `5.10.0+15` | 大类可选、统一分类选择器、钱包多分类规则、旧预算迁移、保存后回首页 |
| 智能输入 | `5.11.0+16` | 截图类别编辑与批量选择、商家学习、真实语音、混合解析和确认卡 |

## 7. 测试与验收

每个阶段采用测试先行：先写能复现缺陷的失败测试，再实现最小修复。

自动测试至少覆盖：

- 主题切换时所有已缓存页面和新路由页面使用新颜色，接口请求次数不增加。
- 大类、子类选择及钱包后代分类汇总；旧预算迁移后金额一致。
- 截图低置信度、类别修改、批量修改、部分保存失败和重复提交。
- 口语金额、退款、收入、存钱、一句多笔、类别歧义和无类别阻止保存。
- 报告所有金额来自规则特征，少数据不生成强建议，缓存键随数据版本变化。
- 图表仅改变视觉高度，提示框仍返回真实金额。
- 导航快速连续点击、手势中断、减少动态效果和页面状态保持。

Android 16 实机验收至少覆盖：

- 六套主题从浅色切深色、深色切浅色后，状态栏、页面、底栏、手势区和已缓存页面同步。
- 60Hz 和高刷新率下导航连续切换无明显掉帧。
- 手动、截图和语音记账保存后均只产生预期账单并回到首页。
- 杀进程、重启、改时区和省电模式下通知状态可解释且可恢复。

## 8. 非目标

- 本轮不构建投资建议、信用评分或自动代替用户修改账单。
- 模型不直接写数据库，不自动更改用户确认过的类别。
- 流星动效不使用持续粒子雨、强光晕或影响阅读的全屏动画。
- 通知方案确认前，不删除当前通知实现。
