# 小满记账：主题按钮原点扩散切换设计

日期：2026-10-12

状态：江泽锦已于 2026-10-13 批准并要求实现；Flutter 动效及入口已接入，真机验收待进行。

## 目标与边界

点击「我的 → 主题配色」的圆形色板后，新主题从该色板的圆心向外扩散，逐步覆盖当前画面。不是纯色圆盘遮住内容，也不是全屏同时渐变。文字、卡片、图标与底部导航在扩散边界内一起变成目标主题。页面、滚动位置、输入内容及导航栈保持不变。

实现覆盖现有六种配色，重点验证雾蓝与极夜、深墨与浅色之间双向切换。不修改导航滑动、地区选择、记账数据及通知业务。不新增第三方动效库，不更新版本号、不构建 APK。

## 当前架构依据

- `frontend/lib/core/theme.dart`：`AppColors.apply` 更新全局颜色及通知器；许多页面直接读取静态颜色 getter。
- `frontend/lib/main.dart`：`XiaojiaApp` 监听主题，`AppSystemUi` 负责系统栏样式及底部安全区背景。
- `frontend/lib/modules/profile/profile_page.dart`：圆形色板调用 `_changeScheme`，先写入 SharedPreferences 再直接切换颜色，没有空间过渡。
- 根主题重建和页面局部颜色重建已存在，保留这套通知机制，扩散组件不成为第二个主题状态源。

## 方案比较

1. **推荐：旧画面截图遮罩，圆形揭示真实新主题。** 保持唯一真实页面树，不重新请求数据；每帧只改变截图遮罩。代价是单次截图准备和临时纹理内存，需要失败降级及及时释放。
2. **所有颜色逐帧插值。** 临时纹理需求小，但所有区域同时变化，不符合从按钮向外扩散，且全局颜色逐帧变动会扩大重建范围。
3. **并列渲染两个主题页面树。** 可以揭示目标页面，但当前静态全局颜色不支持两个独立主题；复制页面会增加状态、网络请求和内存风险，故不采用。

## 用户可见动效

- 原点是被点击圆形色板的几何中心，不使用手指随意落点或整行标签中心。点标签触发时也从对应色板中心开始。
- 起始半径约 20 逻辑像素，与 40dp 色板呼应；终点半径取原点到四个屏幕角落的最大距离，额外留 2dp 余量避免角落残影。
- 正常扩散时长 360ms，快起慢收，无弹跳、粒子、模糊光晕及额外流星效果。
- 图标与正文不移动、不缩放，卡片尺寸不变。六个色板的选中标记以全局目标主题为准，不保留过期本地索引。
- 只在手动选择不同主题时播放。重复点击当前主题、启动读取保存主题、系统无障碍减少动画时不播放空间扩散。
- 减少动画采用直接切换：不截图、不等待 360ms；保证辅助功能不因装饰动画被阻塞。

## 实现职责与时序

新增 `frontend/lib/core/theme_reveal.dart`，在 MaterialApp 的 builder 中置于 AppSystemUi 外侧，包住导航器、应用内弹窗、底部导航及安全区背景。通过继承作用域暴露 `changeTheme(scheme, globalOrigin)`，色板入口只提交目标主题及圆心。主题依然只有 AppColors 一套状态。

正常时序：

1. 校验目标主题与原点，取得根渲染边界尺寸及局部圆心坐标。
2. 捕获当前应用画面一次，图像仅存内存，不写磁盘、不上传；截图像素比上限为 2，避免高分辨率手机放大纹理开销。
3. 在切换主题之前安装完整旧画面遮罩，并保证至少完成一次绘制；不得让目标主题抢先露出造成闪屏。
4. 调用 AppColors.apply 更新唯一真实页面，禁用 MaterialApp 自带的颜色插值，避免扩散区域内新颜色仍在混合。旧画面遮罩只覆盖真实页面的外侧，圆内透明，显示目标主题。
5. 新主题完成绘制后开始 360ms 扩散，动画监听器只重绘遮罩，不驱动整页每帧 rebuild。
6. 扩散结束移除遮罩，释放 ui.Image 和动画资源。主题偏好写入串行化，保证最后一次有效选择成为最终保存值。

这里修正此前「结束后才提交底层主题」的技术表述：用户视觉上是渐进切换，但底层必须在旧画面遮罩保护下提前切换，才可以显示圆内的新主题。不能用全局静态 getter 同时构造两个独立主题页面。

## 系统栏与平台限制

- Flutter 绘制的状态栏背板、应用底部导航及系统底部安全区背景包含在根渲染边界内，参与同一扩散遮罩。
- Android 时钟、电量及系统导航图标不是 Flutter 画面的一部分，不能截图或圆形裁剪。设计不承诺系统图标逐像素扩散。
- 动画期间系统图标先保留旧明暗，圆形揭示完全覆盖对应系统栏区域后切到目标明暗；结束必须恢复目标主题完整样式，避免永久使用临时样式。
- AppSystemUi 的 AnnotatedRegion、SystemChrome 与 Android bridge 使用同一过渡样式来源，不允许页面及根组件竞争写入。
- Android 16 的实际系统栏表现列为真机验收项；Flutter 测试通过不代表原生栏行为已经验证。iOS 保留现有接口，采用同一 Flutter 扩散策略，不引入 Android 独占页面。

## 中断、错误与资源约束

- 捕获阶段再次选择：仅保留最新目标与其原点，过期截图结果立即释放。
- 扩散中再次选色：先清理当前遮罩并使当前目标成为稳定画面，再对最新请求启动新扩散；始终最多一个动画、一个持有截图，不叠加动画队列。验收确认快速点击不会出现旧主题回跳。
- 页面切换、返回、窗口尺寸变化或应用进入后台：结束视觉过渡、保留最后有效目标、释放资源，不让旧截图覆盖新页面或重排后的窗口。
- 截图异常、无法获得渲染尺寸、原点不在可见画面：立即完成主题切换，不保留遮罩或一直显示加载状态。
- 偏好保存失败：不回滚已完成的视觉切换，提示「配色已切换，但保存失败，请重试」，重启可能恢复旧主题；失败不能吞掉，也不能弹出阻塞式错误对话框。
- 当前实现不含平台视图/视频主题入口；若未来出现无法截图的内容，在该画面降级直接切换。
- 截图含用户信息，内存使用结束立即释放，不持久缓存，不用于日志。

## 验收与测试

先新增失败测试，再实现，最后运行定向及全量 Flutter 测试：

1. 几何测试：屏幕中心、边缘、角落原点均完全覆盖四角；坐标转换包含滚动与安全区偏移。
2. 控件测试：切换前遮罩可见；中途存在圆形揭示；结束遮罩消失；文本、滚动位置及 State 身份保持。
3. 入口测试：点击任意色板/标签使用正确圆心；选中标记和全局主题一致；相同配色不创建截图。
4. 并发与失败测试：连续切换最终主题及保存值为最后选择；过期捕获结果不可安装；捕获异常、持久化失败、后台和尺寸变化正常收尾。
5. 系统栏测试：临时样式与目标样式的时序；结束后 AnnotatedRegion 与桥接参数一致，不遗留旧明暗。
6. 无障碍测试：减少动画不截图、不扩散，主题仍更新；色板保留语义名称和选中状态。
7. 性能检查：遮罩动画不触发页面逐帧构建；不每帧截图或网络请求。真机 profile 检查 60Hz 下帧时间目标 16.7ms 内，120Hz 目标 8.3ms 内；未测量不得宣称达到目标。
8. 真机录屏：六色互切、连续快速点击、深浅双向切换、返回和切页，检查闪屏、圆心错位、边角残影、图标明暗及内存回收。
